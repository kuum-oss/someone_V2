# ТЕХНІЧНИЙ ЗВІТ: ПРОЕКТУВАННЯ ТА РЕАЛІЗАЦІЯ БАЗИ ДАНИХ
## Проект "Smart Organizer"

### Загальна інформація
**Тема:** Розробка реляційної моделі даних та інтеграція СУБД MySQL.


---

### Опис етапу розробки
**Мета:** Побудова надійної системи збереження даних, що забезпечує цілісність інформації про користувачів, книги та транзакції.
**Виконані завдання:**
1. Проектування логічної схеми бази даних.
2. Налаштування сервера MySQL та конфігурація параметрів підключення.
3. Реалізація SQL-скриптів для автоматичного розгортання структури таблиць.
4. Оптимізація роботи з великими бінарними об'єктами (BLOB).

---

### Архітектура бази даних
Інформаційна модель системи включає наступні ключові сутності:
- **Users:** Облікові записи, права доступу та баланс балів.
- **Books:** Повні метадані книг, бінарний контент (файли та обкладинки), типи видань.
- **Orders:** Журнал замовлень фізичних копій книг.
- **Notifications:** Система внутрішніх сповіщень.
- **Blacklist:** Механізм блокування доступу.

---

### SQL-структура (DDL фрагменти)
Ініціалізація структури виконується автоматично при старті додатка:

```sql
-- Таблиця користувачів з підтримкою балів
CREATE TABLE IF NOT EXISTS users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    email VARCHAR(255) NOT NULL UNIQUE,
    password VARCHAR(255) NOT NULL,
    is_admin BOOLEAN NOT NULL DEFAULT FALSE,
    points INT NOT NULL DEFAULT 5
);

-- Таблиця книг з підтримкою зберігання файлів безпосередньо в БД
CREATE TABLE IF NOT EXISTS books (
    id INT AUTO_INCREMENT PRIMARY KEY,
    user_id INT NOT NULL,
    title VARCHAR(255) NOT NULL,
    author VARCHAR(255),
    genre VARCHAR(100),
    year VARCHAR(20),
    cover MEDIUMBLOB,
    file_content LONGBLOB, -- Зберігання контенту книги
    book_type ENUM('ELECTRONIC', 'PHYSICAL') NOT NULL DEFAULT 'ELECTRONIC',
    is_available BOOLEAN NOT NULL DEFAULT TRUE,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);
```

---

### Аналіз та висновки
Обрана архітектура бази даних дозволяє системі бути повністю автономною.
- **Цілісність:** Використання Foreign Keys та каскадних видалень гарантує відсутність "сміттєвих" даних.
- **Продуктивність:** Налаштування `max_allowed_packet` та використання відповідних типів BLOB забезпечує стабільну роботу з файлами великого розміру.
- **Автономність:** Механізм автоматичного створення таблиць спрощує розгортання проекту в нових середовищах (наприклад, через Docker).
