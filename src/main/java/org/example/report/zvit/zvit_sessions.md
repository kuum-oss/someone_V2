### Механізм роботи з сесіями
У проекті "Smart Organizer" сесії використовуються для:
- **Аутентифікації:** Після успішної перевірки пароля об'єкт `User` зберігається в атрибуті сесії `currentUser`.
- **Авторизації:** Кожен запит до захищених ресурсів (скачування, кошик) перевіряє наявність активного користувача в сесії.
- **Безпеки:** Використовується метод `ctx.consumeSessionAttribute()` при виході, що гарантує повне очищення даних на сервері.

---

### Реалізація (Фрагмент WebServer.java)
```java
package org.example.infrastructure.web;

import io.javalin.http.Context;
import org.example.core.entity.User;

/**
 * Логіка управління сесіями користувачів.
 */
public class WebServer {
    private void setupRoutes() {
        // Обробка входу: створення сесії
        app.post("/login", ctx -> {
            if (authService.login(email, password)) {
                ctx.sessionAttribute("currentUser", authService.getCurrentUser());
                ctx.redirect("/");
            }
        });

        // Обробка виходу: знищення сесії
        app.get("/logout", ctx -> {
            ctx.consumeSessionAttribute("currentUser");
            ctx.redirect("/");
        });

        // Використання даних сесії в моделі відображення
        app.get("/", ctx -> {
            User user = ctx.sessionAttribute("currentUser");
            model.put("currentUser", user);
            render(ctx, "templates/library.ftl", model);
        });
    }
}
```

### Аналіз та висновки
Використання сесій дозволило трансформувати "stateless" HTTP протокол у середовище, орієнтоване на користувача.
- **Зручність:** Користувачеві не потрібно вводити дані при кожному переході між сторінками.
- **Надійність:** Дані сесії зберігаються на сервері, що безпечніше, ніж зберігання всієї інформації на стороні клієнта.
- **Гнучкість:** Система підтримує розмежування прав доступу (Admin/User) на основі об'єкта, що зберігається в сесії.
