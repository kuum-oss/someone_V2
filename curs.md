# КУРСОВИЙ ПРОЄКТ

## Тема: Розробка інформаційної системи «Smart Organizer» для управління цифровою бібліотекою

---

### РЕФЕРАТ

Курсовий проєкт містить 68 сторінок, 2 таблиці, 55 рисунків, список використаних джерел з 20 найменувань, 5 додатків.

Розробка програмного продукту «Smart Organizer»
Автор курсового проєкту: Пасько Дмитро Олександрович

Перелік ключових слів: БАЗА ДАНИХ (БД), КЛІЄНТ, КОРИСТУВАЧ, ОНЛАЙН-СЕРВІС, ПЛАТФОРМА, ПРОГРАМНИЙ ПРОДУКТ, ЦИФРОВА БІБЛІОТЕКА, МЕТАДАНІ, APACHE TIKA, CLEAN ARCHITECTURE.

Об’єктом розроблення є програмний продукт «Smart Organizer».

Мета курсового проєкту полягає в розробці програмного продукту «Smart Organizer», для забезпечення зручного доступу до управління цифровою бібліотекою, автоматичного вилучення метаданих та організації зберігання електронних книг.

Інструменти розроблення кваліфікаційної роботи: розробка прототипу програмного продукту в середовищі розробки IntelliJ IDEA з використанням БД, яка реалізована за допомогою інструменту візуального програмування MySQL Workbench.

Апаратура використана при розробленні курсового проєкту – персональний комп’ютер та периферійні пристрої.

Результати досягнуті в процесі роботи: були задіяні дані з БД і використанні для коректної роботи серверної частини (Javalin) та для відображення даних на веб-сторінках (FreeMarker), а також в десктопному інтерфейсі (Swing/FlatLaf).

Одержані результати можуть бути використані для забезпечення користувачів зручним та функціональним онлайн-сервісом із систематизації персональних медіа-бібліотек, а з поступовим покращенням і виходом на міжнародний ринок, зможе приносити хороший прибуток.

### 1 ХАРАКТЕРИСТИКА ТА АНАЛІЗ ПРЕДМЕТНОЇ ОБЛАСТІ

#### 1.1 Характеристика предметної області
Предметна область охоплює сферу управління цифровим контентом, зокрема електронними книгами. Основна проблема користувачів – відсутність структурованого сховища, що веде до втрати інформації та складнощів у пошуку.
Система «Smart Organizer» спрямована на автоматизацію наступних процесів:
- Зберігання файлів книг різних форматів (PDF, EPUB, FB2).
- Вилучення метаданих (автор, назва, рік) для автоматичної класифікації за допомогою Apache Tika.
- Організація фізичних та електронних примірників у єдиній базі.
- Забезпечення розмежування прав доступу (користувач/адміністратор).

#### 1.2 Аналіз існуючих рішень
В даному підрозділі розглянуто системи та онлайн-сервіси, що надають послуги з організації цифрових бібліотек та управління книжковим контентом.

Calibre є потужним менеджером електронних книг з відкритим вихідним кодом. Він дозволяє конвертувати формати, редагувати метадані та синхронізуватися з рідерами. Проте інтерфейс системи є перевантаженим для пересічного користувача, а мобільна версія потребує додаткових налаштувань.

#### 1.4 Функціональні можливості системи
Розроблена система «Smart Organizer» покликана поєднати переваги десктопних менеджерів (повний контроль над файлами) та сучасних веб-сервісів (доступність, зручність). Система забезпечує:
1. **Авторизацію та реєстрацію:** безпечний вхід за допомогою email та хешованого пароля (BCrypt).
2. **Керування бібліотекою:** завантаження книг, автоматичне зчитування метаданих через Apache Tika та пошук обкладинок онлайн.
3. **Замовлення фізичних книг:** можливість оформлення замовлень на паперові примірники; списання бонусних балів не застосовується.
4. **Адміністрування:** перегляд статистики через Admin Dashboard, керування користувачами, нарахування бонусних балів.
5. **Гібридний інтерфейс:** можливість роботи через десктопний GUI (Swing) або Web-інтерфейс (Javalin).

### 2 РОЗРОБЛЕННЯ ЗАГАЛЬНОЇ КОНЦЕПЦІЇ СИСТЕМИ

#### 2.1 Вибір і обґрунтування програмних рішень
Для реалізації проєкту обрано наступний стек технологій:
- **Java 21:** забезпечує високу продуктивність та підтримку сучасних мовних конструкцій (Records, Virtual Threads).
- **Maven:** автоматизація збірки та управління залежностями (pom.xml).
- **MySQL:** надійна реляційна СУБД для зберігання даних про користувачів, книги та замовлення.
- **Javalin 6.1.3:** легковажний фреймворк для реалізації веб-інтерфейсу та REST API.
- **Swing (FlatLaf 3.4.1):** створення сучасного десктопного інтерфейсу з підтримкою темної теми.
- **Apache Tika:** інструмент для автоматичного вилучення метаданих з файлів різних форматів.

#### 2.2 Інформаційна модель системи

Інформаційна модель системи «Smart Organizer» базується на реляційній структурі, реалізованій за допомогою СУБД MySQL. Вона забезпечує зберігання метаданих книг, бінарного контенту, профілів користувачів та історії транзакцій.

##### 2.2.1 Концептуальна модель предметної області

Центральними сутностями системи є:
1.  **User (Користувач)** – містить облікові дані (email, хешований пароль), роль (адмін/користувач) та баланс бонусних балів.
2.  **Book (Книга)** – основна сутність, що зберігає:
    *   Метадані (назва, автор, жанр, рік, серія, мова, опис).
    *   Технічні дані (шлях до файлу, оригінальна назва, розмір).
    *   Бінарні дані (обкладинка `cover`, фото автора `author_photo`, контент файлу `file_content` у форматі `LONGBLOB`).
    *   Атрибути доступності (тип видання: електронне/фізичне, статус публічності).
3.  **Order (Замовлення)** – пов’язує користувача з фізичною книгою, фіксує статус (PENDING, SHIPPED, DELIVERED) та час створення.
4.  **Notification (Сповіщення)** – система внутрішніх повідомлень для інформування користувачів про нові замовлення або системні події.
5.  **Blacklist (Чорний список)** – таблиця для блокування доступу за email із зазначенням причини.

##### 2.2.2 Вхідні дані системи

Вхідними даними є:
*   Файли електронних книг (PDF, EPUB, FB2, MOBI).
*   Метадані, що вводяться користувачем вручну через форми GUI або Web.
*   Зовнішні дані з онлайн-сервісів (Google Books API), що використовуються для автоматичного дозаповнення пропущених полів.
*   Облікові дані для реєстрації та авторизації.

##### 2.2.3 Вихідні дані системи

Вихідними даними є:
*   Сформовані списки книг з відфільтрованими та відсортованими параметрами.
*   Файли книг для завантаження (download).
*   Статистичні звіти про обсяг бібліотеки та використання дискового простору.
*   Статуси замовлень фізичних копій.

#### 2.3 Функціональна модель системи

Система реалізує наступні ключові функції:
1.  **Автоматичний імпорт:** Сканування директорій, розпізнавання форматів та вилучення метаданих за допомогою бібліотеки Apache Tika.
2.  **Нормалізація даних:** Очистка назв від технічного "сміття", виправлення транслітерації та приведення жанрів до єдиного стандарту через `TextNormalizer`.
3.  **Гібридне зберігання:** Можливість зберігати файли як у локальній файловій системі, так і безпосередньо в базі даних (для портативності).
4.  **Багатокористувацький доступ:** Розмежування прав доступу (користувачі бачать лише свои книги, адміни керують усією системою).
5.  **Магазин та замовлення:** Система балів (points) для придбання доступу до публічних книг та оформлення замовлень на фізичні видання.

#### 2.4 Алгоритм роботи системи

Основним алгоритмічним вузлом є процес обробки нової книги (`ExtractMetadataUseCase`):

1.  **Визначення формату:** Перевірка розширення та MIME-типу файлу.
2.  **Локальна екстракція:** Використання `TikaMetadataAdapter` для читання внутрішніх тегів файлу.
3.  **Зовнішній пошук:** Якщо локальних даних недостатньо (відсутній жанр або опис), система звертається до `ExternalMetadataGateway`.
4.  **Нормалізація:** 
    *   `normalizeTitle`: видалення розширень та шляхів з назви.
    *   `normalizeGenre`: мапінг специфічних тегів (наприклад, "sci-fi") на загальні категорії.
    *   `transliterate`: перетворення кириличного трансліту назад у читабельний вигляд.
5.  **Збереження:** Формування об’єкта `StoredBook` та запис у БД через `JdbcBookRepository`.

#### 2.5 Архітектура системи

Проєкт побудований на принципах **Clean Architecture** (Чиста архітектура):
*   **Domain Layer (Entities):** Чисті POJO класи (`Book`, `User`), що не залежать від фреймворків.
*   **Application Layer (Use Cases):** Бізнес-логіка (організація книг, авторизація, управління замовленнями).
*   **Service Layer:** Facade для бізнес-логіки (AuthService, AdminService).
*   **Infrastructure Layer:** Репозиторії (JDBC), UI (Swing) та WebServer (Javalin).

#### 3.1 Проєктування та програмування серверної частини програми

Серверна частина реалізована на Java 21 з використанням Maven як системи збірки. Основні технічні аспекти:

*   **Управління даними (Persistence):** Для взаємодії з MySQL використовується JDBC з пулом з’єднань `Apache Commons DBCP2`. Це забезпечує високу швидкість обробки запитів та ефективне управління ресурсами. Клас `DatabaseInitializer` автоматично створює необхідну структуру таблиць при першому запуску (Idempotent Deployment).
*   **Веб-сервер (Javalin):** Фреймворк Javalin обробляє маршрути (Routes) для Web-інтерфейсу. Реалізовано стрімінг контенту файлів прямо з БД, захист від CSRF та менеджер прав доступу (AccessManager).
*   **Бізнес-логіка (Services):** Сервісний шар ізолює складні операції. Наприклад, `AdminService` забезпечує каскадне очищення даних при видаленні користувача, гарантуючи цілісність системи.

### ДОДАТКИ
**ДОДАТОК А** Схема бази даних (SQL DDL).
**ДОДАТОК Б** Лістинг головного класу ініціалізації системи `Main.java`.

**ДОДАТОК В** Інструкція з розгортання через Docker Compose.

У проекті реалізовано автоматизований цикл розгортання (CI/CD Ready), що дозволяє запустити повну інфраструктуру (додаток + база даних) однією командою.

1.  **Автоматизація в Docker:**
    *   **Dockerfile:** використовує багатоетапну збірку (Multi-stage build). На першому етапі Maven збирає JAR-файл, на другому — легковажний образ JRE 21 запускає додаток.
    *   **Headless Mode:** Додаток автоматично визначає відсутність графічної оболонки та перемикається в режим веб-сервера (порт 8080).
    *   **Healthchecks:** Docker Compose очікує на повну готовність MySQL перед запуском Java-додатка.
    *   **Auto-Migration:** При першому запуску клас `DatabaseInitializer` автоматично створює базу даних `library_db` та всі необхідні таблиці.

2.  **Команди для розгортання:**
    *   Для запуску всієї системи:
        ```bash
        docker-compose up --build
        ```
    *   Після успішного запуску веб-інтерфейс буде доступний за адресою: `http://localhost:8080`.

3.  **Конфігурація середовища:**
    Параметри підключення до БД передаються через змінні оточення (Environment Variables) у файлі `docker-compose.yml`, що дозволяє легко змінювати паролі та адреси без перезбірки коду.
